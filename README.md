# 社区独居老人一键求助 · 上门核实转介回访平台

面向社区独居老人照护场景：老人通过**智能按钮、电话、社区小程序**发起求助后，值班社工在同一条事件中完成
**求助受理 → 研判分类 → 分级转介 → 上门核实 → 后续服务 → 家属沟通 → 回访归档**，
并在归档时联动更新老人照护画像、家属响应表现、邻里协助可信度与下一次主动关怀计划，
支撑社区管理者按风险等级、响应时长、服务类型、回访结果复盘独居老人照护能力。

针对**同一老人一周内多次夜间按键求助**的频繁求助场景，社区端可查看每次求助原因、到场结果、
是否孤独焦虑、是否药物管理混乱及家属参与情况；社工据此发起**长期照护评估**，制定并生效
**长期照护方案**（定期探访、心理陪伴、助餐、家庭医生随访、药盒提醒），平台持续观察
**夜间求助次数、助餐签到、药盒提醒、家属接听率**的变化；方案若无改善，社工发起**个案会商**
（养老顾问、社区医生、家属），协商结论自动写回老人档案。

## 技术栈

- 前端：Vue 3 + Vite + Element Plus + Pinia + Vue Router + ECharts（SSE 实时告警）
- 后端：Spring Boot 3.3 + Spring Data JPA + Redis（登录令牌）+ PostgreSQL
- 基础设施：Docker Compose 一键启动 postgres / redis / backend / frontend

## 一、Docker 一键启动（推荐）

前置：安装 Docker 与 Docker Compose。

```bash
cd 170-b
docker compose up -d --build
```

启动后访问：

| 服务 | 地址 |
| --- | --- |
| 前端页面 | http://localhost:8081 |
| 后端 API | http://localhost:8080/api |

首次启动自动建表并写入 5 个测试账号和 3 位示例老人档案（周桂兰、吴德海、郑秀珍）。

停止与清理：

```bash
docker compose down          # 停止（保留数据卷）
docker compose down -v       # 停止并清空数据库/上传文件
```

## 二、本地开发启动

```bash
# PostgreSQL 15（创建库 eldercare，账号 care / 密码 care123）
createdb -U care eldercare
```

```bash
cd backend

# 或：mvn package -DskipTests && java -jar target/eldercare.jar
```

```bash
cd frontend
npm install        # 如遇官方源慢：npm config set registry https://registry.npmmirror.com
npm run dev
```

浏览器打开 http://localhost:5173 。

## 业务功能与验证路径

### 1. 一条事件贯通全流程（“求助—核实—上门—转介—服务—家属沟通—回访”）

值班工作台 →「模拟一键求助」选择老人与来源（智能按钮/电话/小程序），填写语音内容与定位 →
进入事件详情，依次操作：

1. **值班研判**：生活协助 / 身体不适 / 跌倒风险 / 情绪危机 / 误触，严重程度 低/中/高/紧急；
2. **转介通知**：按严重程度通知网格员 / 邻里志愿者 / 家庭医生 / 120，可登记邻居代报及信息是否清晰，并更新受理/到场状态；
3. **上门核实**：入户方式（钥匙、门禁密码、智能锁授权、邻居/家属开门、破锁、未能入户）、现场照片上传、
   老人状态、是否联系家属、是否需要送医、是否拒绝就医、是否需要临时照护、后续服务建议、家中安全隐患；
4. **家属沟通**：多次拨打接通情况与态度（连续未接通自动判定“家属长期不接电话”）；
5. **后续服务**：临时照护、送医陪诊、日常巡访、助餐、适老化改造、心理陪伴；
6. **回访归档**：好转/平稳/恶化/未联系上 + 满意度 + 下一次主动关怀计划，归档联动更新画像。

右侧固定展示**老人照护画像**（长期独居、燃气报警器、最近家属探访、医生随访结论、历史误触、
基础病、门禁信息、紧急联系人、邻里响应人），底部为全过程时间线留痕。

### 2. 七类特殊风险自动/手动标记，全程沉淀在同一事件

| 风险 | 触发方式 |
| --- | --- |
| 无法开门 | 上门记录“未能入户”或入户方式为未能入户 |
| 定位偏移 | 求助坐标与档案住址距离 > 500 米自动判定（阈值可配） |
| 家属长期不接电话 | 档案联系人已标记，或同一事件累计 ≥2 次未接通 / 联系人累计未接通率超 2/3 |
| 邻居代报信息不清 | 转介时勾选“邻居代报·信息不清”，同时下调该邻里可信度 |
| 老人拒绝就医 | 上门记录勾选 |
| 家中存在安全隐患 | 上门填写隐患描述（自动建议适老化改造） |
| 频繁夜间求助 | 22:00–06:00 求助，近 30 天夜间求助 ≥3 次自动标记（阈值可配） |

### 3. 事件不停在处置结果——归档联动更新

回访归档后系统自动：

- 重算老人**综合风险等级**；
- 更新**家属响应表现评分**（本事件接通率）与联系人接通统计；
- 更新**邻里协助可信度**（有效响应、代报信息质量）；
- 累加**误触记录**；
- 依据跌倒/隐患/情绪危机/临时照护等勾选**增加日常巡访、助餐、适老化改造、心理陪伴**建议；
- 生成**下一次主动关怀计划**（可手动指定，否则按严重程度 1/3/7/14 天自动排期）。

### 4. 社区管理者复盘

「照护能力复盘」页（admin 账号可看全部数据）支持按时间区间统计：
事件总数/夜间/送医、按风险等级分布、按研判类型分布、按服务类型分布、按回访结果分布、
每日求助趋势、平均/最快/最慢响应时长与 15 分钟到场率、七类风险场景出现频次。

### 5. 频繁夜间求助 → 长期照护评估 → 长期照护方案 → 个案会商闭环

种子老人**郑秀珍**在近一周预置了 **3 次夜间求助**完整留痕（每次原因、到场结果不同，含孤独焦虑、
药物管理混乱、家属多次未接），打开「老人画像」即可直接验证：

1. **夜间求助观察**（老人画像页）：按近 7/14/30 天汇总每次夜间求助的**求助原因（语音/研判）、
   到场结果（老人状态、是否送医/临时照护、孤独焦虑、药物混乱）、家属参与（逐次接通情况）**，
   并给出夜间次数、孤独焦虑次数、药物混乱次数、家属接听率；近 7 天 ≥3 次提示“频繁夜间求助”。
   上门核实环节新增**孤独焦虑（含情绪表现）、药物管理混乱（含用药情况）**两个登记项。
2. **发起长期照护评估**：系统自动汇总夜间原因与到场结果，社工补充孤独焦虑、药物管理混乱、
   家属参与度（参与良好/一般/不足）、日常生活/慢病/居家安全评估、照护强度与服务建议；
   评估结论**自动写回老人档案留痕**。
3. **制定并生效长期照护方案**：按评估建议配置**定期探访、心理陪伴、助餐、家庭医生随访、药盒提醒**
   等服务项（频次、责任方），方案生效时记录**基线**（观察周期内夜间求助次数、家属接听率）。
4. **持续观察**（方案跟踪页）：逐项登记探访、助餐签到/失约、药盒提醒是否按时服药、家属联系是否接通；
   平台按周呈现**夜间求助次数、助餐签到、药盒提醒（服药依从率）、家属接听率**的变化趋势图与
   改善中/无明显变化/未见改善且恶化的综合判定。
5. **个案会商**：方案无改善时一键发起，登记**养老顾问、社区医生、家属**等参与方及意见，
   协商结论（含方案调整内容）**自动写回老人档案**，档案页“照护档案留痕”时间线可追溯
   评估 → 方案生效 → 复评 → 会商全过程。

「长期照护方案」菜单汇总全部方案（生效观察中/草案/观察期结束），可按老人筛选。

### 频繁夜间求助长期照护闭环（2026-10-06 实测）

验证环境：JDK 17 + Maven 3.8 + Node 22 + PostgreSQL 15（端口 5433）+ Redis 7。

1. **后端编译打包**：`mvn package -DskipTests` 成功，启动后自动建表并为郑秀珍播种近一周 3 次夜间事件。
2. **夜间求助观察**：`GET /api/elders/3/night-review?days=7` 返回夜间求助 **3 次**、
   到场发现**孤独焦虑 2 次、药物管理混乱 2 次**、家属联系 6 次仅接通 1 次，**接听率 17%**，
   每次事件的原因（语音/研判）、到场结果、家属逐次接通情况均可查看，`frequentFlag=true`。
3. **长期照护评估**：提交评估后系统自动汇总每次夜间原因（如“胸口闷，晚饭药没吃…”）与到场结果，
   夜间次数快照 3、家属参与自动判为“参与不足”，评估结论写入档案留痕。
4. **方案生效与基线**：含定期探访/心理陪伴/助餐/家庭医生随访/药盒提醒 5 个服务项的方案生效，
   状态 `ACTIVE`，基线夜间求助 3 次/28天、基线家属接听率 17%。
5. **签到登记**：登记助餐签到 5 次+失约 1（签到率 83%）、药盒提醒 6 次其中按时服药 5（依从率 83%）、
   家属联系 3 次接通 2（接听率 67%，较基线 +50 个百分点）、探访与心理陪伴各 1 次。
6. **方案后夜间求助**：再次夜间按键自动带上 `FREQUENT_NIGHT_HELP`；效果接口按周输出四项指标与综合判定，
   社工保存“无明显变化”复评，复评写入档案。
7. **个案会商写回档案**：登记养老顾问周顾问、社区医生钱医生、家属郑伟及社工意见，提交协商结论后
   `writtenBackToArchive=true`；`GET /api/elders/3/archive-notes` 时间线依次包含
   评估、方案生效、效果复评、个案会商四条留痕。
8. **前端**：最新源码 `npm run build` 构建成功（含 CarePlanListView、CarePlanDetailView），
   Vite dev 下各变更模块（老人画像、事件处置、方案列表/跟踪）均 200 正常编译，登录与 /api 代理正常。
